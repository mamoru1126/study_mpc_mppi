07. MPC と MPPI の比較

この章のゴール

  • 2 つの方法の式とアルゴリズムを並べて、対応を説明できる
  • 得意・苦手を、具体的な場面 (局所解、段差のコスト、制約、計算資源) で説明できる
  • どちらを選ぶか、どう組み合わせるかの考え方を持つ

つながり 01〜06 章 のまとめです。最後に、同じ場面を両方の方法で解くデモで確かめます。

1. 同じ問題、違う解き方

MPC (ガウス・ニュートン法・SQP) MPPI
解く問題 01 章 の有限ホライズン最適制御問題 同じ
変数 入力の列 \(U\) (multiple shooting なら状態も) 入力の列 \(U\) (ばらつきの平均として)
まわりの調べ方 微分: \(A_t\), \(B_t\), ヤコビアン \(J\) \(K\) 本のサンプル \(\varepsilon^k \sim \mathcal N(0, \Sigma)\)
改善案の作り方 \(J^\top J\, \Delta = -J^\top r\) (制約があれば QP) \(\Delta = \sum_k w_k \varepsilon^k\)、\(w_k \propto e^{-S_k/\lambda}\)
1 回の更新が意味するもの \(\Delta = -(J^\top J + \mu D)^{-1} J^\top r\) \(\Delta \approx -(\Sigma/\lambda)\, \nabla F_\lambda\) (2 次なら \(-(A + \lambda\Sigma^{-1})^{-1} \nabla S\))
1 周期の反復 収束まで、または RTI で 1 回 1 回 (Nav2 の既定)
1 周期の計算 微分と、連立方程式または QP \(K \times N\) 回のモデル計算 (並列にできる)
出力 \(u_0\) を実行して、案をずらす 同じ

06 章 で見たとおり、どちらも「今の案のまわりを調べて、良くなる向きに少し直す」をくり返しています。

  • MPC は 元のコスト の傾きを 微分で正確に 求める
  • MPPI は ぼかしたコスト の傾きを サンプルで推定 する

この違いから、次の得意・苦手が出てきます。

1.1 アルゴリズムを並べる

NMPC (single shooting、ガウス・ニュートン法 + LM 法)

# U = shift(前回の答え)
for it in range(iters):
    X = rollout(x_hat, U)
    r, J = residual_and_jacobian(X, U)
    H, g = J.T @ J, J.T @ r
    dU = solve(H + mu * diag(H), -g)
    U = clip(U + dU, u_min, u_max)
send(U[0])

MPPI

# U = shift(前回の答え)
eps = normal(0, Sigma, (K, N))
S = [cost(rollout(x_hat, U + eps[k]))
     for k in range(K)]
w = exp(-(S - S.min()) / lam)
w = w / w.sum()
U = U + w @ eps
send(U[0])

NMPC は、コストが下がらなかったときに \(\mu\) を大きくしてやり直す処理を省いています (04 章 4 節)。どちらも「前回の答えをずらして始め、まわりを調べて直し、最初の 1 手を送る」という同じ骨組みで、違うのは真ん中の「調べて直す」部分だけです。

2. 得意・苦手

観点 MPC (勾配法・SQP) MPPI
収束と計算回数 ◎ 傾きと曲がり具合を使い、数回の反復で収束する。デモでは 1 周期のコスト評価が平均 6 回ほど △ \(K\) 本のロールアウトが要る (デモは 300 本、Nav2 の既定は 1000 本)。サンプルが有限なので推定の誤差が残る
制約 ◎ 入力・状態の制約を QP の制約として正確に扱える △ 入力は上下限で切る。状態の制約は罰として入れるだけで、守られる保証はない
コストの形 × 微分できる必要がある。段差 (接触したら罰) は傾きが 0 で効かない ◎ 計算できれば何でもよい (段差、コストマップの参照など)
局所解 × 出発点の近くの答えで止まる。真正面の障害物の手前で止まる ○ ゆらぎで左右の偏りができ、離れた答えにも届く。ただし左右の候補を平均すると、真ん中 (ぶつかる側) に寄ることがある
モデル △ 微分 (ヤコビアン) が要る。自動微分で用意することが多い ◎ 中身の分からないモデル (シミュレータ、学習したモデル) でもよい
計算資源 ○ 構造を使った QP で軽い。反復回数しだいで計算時間が変わる ◎ サンプルごとに独立で、GPU・SIMD 向き。1 周期の計算量が一定
出力のなめらかさ ◎ 乱数を使わないのでなめらか △ 乱数でガタつく。平滑化や「入力の変化」の罰で抑える
理論 ◎ 安定性や、制約を満たし続けられることの理論がある (終端コスト・終端制約を使う) △ サンプルが有限のときの最適性や安定性の保証は弱い
調整する値 重み \(Q, R, P\)、ホライズン、ソルバーの設定 \(\lambda\)、\(\Sigma\)、\(K\)、ホライズン、平滑化、コストの重み

3. デモで確かめる

左が NMPC (ガウス・ニュートン法、1 周期に 3 回反復)、右が MPPI です。モデル・コスト・場面は同じで、違うのは解き方だけです。

同じ場面を演習のコード (exercises/robot2d.py) で走らせた結果です。

場面 NMPC MPPI (\(K = 300\), \(\lambda = 1\))
少しずれて立つ人・なめらかな罰 10.4 秒でゴール 11.3 秒でゴール
真正面の人・なめらかな罰 手前で止まり、時間切れ 11.7 秒でゴール
少しずれて立つ人・接触だけ罰 9.8 秒でゴール、接触 1 回 11.0 秒でゴール、接触なし (すき間 0.05 m)
横切る人・なめらかな罰 10.7 秒でゴール 11.4 秒でゴール
2 人・なめらかな罰 10.8 秒でゴール 11.6 秒でゴール

見どころ:

  • 少しずれて立つ人・なめらかな罰: どちらも着きます。NMPC は入力がなめらかで、1 周期のコスト評価が MPPI (301 回) より 2 桁少ない
  • 真正面の人: 左右対称で横へ動く理由がなく、NMPC は手前で止まります (04 章 8.1 節)。MPPI はゆらぎで左右の偏りができて回り込みます
  • 接触だけ罰: 罰が段差なので傾きが 0 になり、NMPC は人を無視して接触します。MPPI は接触するサンプルの重みがほぼ 0 になるので避けます。ただし、すき間は 0.05 m しかありません。接触しない限り罰がないので、余裕を取る理由がないからです。余裕がほしければ、なめらかな罰も足します
  • MPPI の \(\lambda\) を小さくすると最良の 1 本に引きずられてガタつき、大きくすると更新が進まなくなります (05 章 5 節)

4. どう選ぶか

MPC が向いている場面

  • モデルとコストがなめらかで、微分を用意できる (マニピュレータ、ドローン、良いモデルのある車両など)
  • 制約を確実に守りたい (入力の限界、安全に関わる状態の制約)
  • なめらかな入力がほしい。安定性の保証がほしい
  • 計算資源が限られている (組み込みの CPU)

MPPI が向いている場面

  • コストが複雑・なめらかでない (コストマップ、接触の罰、地形の通りやすさ)
  • よけ方が何通りもある (左右どちらからでも、など)
  • モデルが中身の分からないもの (シミュレータ、学習したモデル)
  • GPU や SIMD で並列に計算できる
  • 例: Nav2 のようなコストマップを使う移動ロボット、オフロードの高速走行 (元の論文)

組み合わせる

  • MPPI で大まかな案 (どちら側からよけるか) を決め、NMPC の初期値にして仕上げる
  • NMPC の初期値を、複数の候補 (左右など) から選ぶ
  • MPPI の出力を平滑化したり、入力の変化に罰をつけたりして、なめらかさを補う

5. よくある誤解

  • 「MPPI は最適化していない (ただのランダム探索)」 → 06 章 のとおり、ぼかしたコストの坂を下る勾配法になっています。2 次のコストなら LM 法と同じ形です
  • 「MPC は必ず最適な答えを出す」 → 非線形なら局所的な最適解です。しかも「モデルが正しければ」の最適です
  • 「λ は温度なので物理的な意味がある」 → Nav2 のパラメータ名が temperature なのは、式の形が統計物理と似ているからで、λ はコスト差の目盛りです (05 章 3 節)
  • 「サンプルを増やせば MPPI はいくらでも良くなる」 → 推定の誤差は減りますが、ぼかしたコスト \(F_\lambda\) の坂を下ることは変わりません。ゆらぎ \(\Sigma\) が届かない範囲は見えません

理解度チェック

  1. MPC と MPPI の 1 回の更新は、それぞれ何の坂を、どうやって求めた傾きで下っているか?
  2. 制約を確実に守りたいとき、どちらが向いているか。それはなぜか?
  3. 「接触だけ罰」のデモで、MPPI は接触しなかったが、すき間は 0.05 m しかなかった。なぜか。どうすれば余裕を取れるか?
  4. 真正面の人のデモで NMPC を回り込ませるには、どんな工夫が考えられるか?
  5. GPU があるときに MPPI が有利なのはなぜか?
答えの例
  1. MPC (ガウス・ニュートン法・LM 法) は元のコスト \(S\) の坂を、微分で正確に求めた傾きで下る。MPPI はぼかしたコスト \(F_\lambda\) の坂を、サンプルで推定した傾きで下る。
  2. MPC。制約を QP の制約として扱えるので、近似の範囲で正確に守れる。MPPI は状態の制約を罰で扱うだけなので、守られる保証がない。
  3. 段差の罰は接触しない限り 0 なので、余裕を取る理由がないから。安全距離の内側に入った深さに比例するような、なめらかな罰も足せばよい。
  4. 左右それぞれに曲がる初期値から解いて良いほうを使う、MPPI など別の方法で初期値を作る、左右の対称性を崩す小さなコスト (例: 右側通行を少し好む) を足す、など。
  5. サンプルごとのロールアウトとコスト計算が互いに独立なので、同時に何千本も計算できるから。
