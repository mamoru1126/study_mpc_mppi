要点

MPC と MPPI は、どちらも「先を予測して、いちばん良い動かし方を選ぶ」制御。押さえるべき点は次の 5 つ。

  1. どちらも「モデルで未来を予測する → コストで採点する → いちばん良い入力の列を選ぶ → 最初の 1 手だけ実行する → また計画し直す」をくり返す。違うのはいちばん良い入力の探し方だけ。
  2. 1 次元の台車でコストを 2 乗の和にすると、コストは入力の 2 次関数になる。MPC の答えは平方完成で求まり、1 手先だけ見るなら「ずれに比例した入力」（P 制御）になる。
  3. 入力に上限があると「定義域つきの 2 次関数の最小値」になる。頂点が範囲の外なら、範囲の端を選ぶ。
  4. 2 輪ロボットや「ぶつかったら罰」のコストが入ると平方完成できない。MPC は微分（傾き）を使って少しずつ谷を下る。MPPI は微分を使わず、正規分布でばらまいた候補を走らせ、指数関数 \(e^{-S/\lambda}\) の重みで平均する。
  5. 温度 \(\lambda\) は「コストの低い候補をどれだけ信じるか」。小さいと最良の候補だけ、大きいとただの平均になる。候補が十分多ければ、MPPI の 1 回の更新は勾配降下法の 1 歩とほぼ同じになる（発展）。

新しい道具はいらない。使うのは次の範囲だけで、行列と偏微分は使わない。変数が 2 つ以上ある所は「1 文字だけ動かし、ほかは定数とみる」で済ませる。

モデル：動きを漸化式で書く

いちばん簡単な例から始める。まっすぐなレールの上を動く台車（1 次元のロボット）を考え、位置を \(x\)［m］、速度の指令を \(u\)［m/s］とする。制御では、位置のように「今の様子」を表す量を状態、速度の指令のように「こちらが決められる量」を入力と呼ぶ。

コンピュータは時間を連続的には扱わず、一定の時間 \(\Delta t\)（たとえば 0.1 秒）ごとに状態を測り、入力を決める。\(n\) ステップ目の位置を \(x_n\)、入力を \(u_n\) と書くと、速度 \(u_n\) で \(\Delta t\) 秒進むので

\[ x_{n+1} = x_n + u_n\,\Delta t \]

となる。これは数列の漸化式そのものだ。\(u_n\) が一定なら、公差 \(u\,\Delta t\) の等差数列になる。このように「今の状態と入力から、次の状態を計算する式」をモデルと呼ぶ。

予測：入力を決めれば未来が計算できる

漸化式をくり返し使えば、入力の列 \(u_0, u_1, \dots\) を決めるだけで、未来の位置がすべて計算できる。

\[ \begin{aligned} x_1 &= x_0 + u_0\,\Delta t \\ x_2 &= x_1 + u_1\,\Delta t = x_0 + (u_0 + u_1)\,\Delta t \\ x_n &= x_0 + \Delta t \sum_{j=0}^{n-1} u_j \end{aligned} \]

何ステップ先まで予測するかを予測ホライズンと呼び、そのステップ数を \(N\) で表す。実際のロボットでは、\(\Delta t = 0.05\) 秒、\(N = 56\)（2.8 秒先まで）のような値を使う（Nav2 の MPPI の既定値）。この資料では、手計算しやすいように \(\Delta t = 1\) 秒とする。

コスト：計画に点数をつける

次に、入力の列が良いか悪いかを 1 つの数で表す。目標の位置を \(g\) として、次の \(J\) をコスト関数と呼ぶ。小さいほど良い計画だ。

\[ J = \sum_{n=1}^{N} (x_n - g)^2 \;+\; \rho \sum_{n=0}^{N-1} u_n^2 \]
  • 第 1 項は、目標からのずれの 2 乗の合計。予測した各時刻で目標に近いほど小さい。
  • 第 2 項は、入力の大きさの 2 乗の合計。急に大きく動かすほど大きい。電池を節約したり、乗せた物をこぼさないようにしたりするためのブレーキ役。
  • \(\rho\)（ロー）は 2 つの項のつり合いを決める正の数で、重みと呼ぶ。大きいほど穏やかな動きを好む。

なぜ 2 乗なのか

  • 符号が消える。右にずれても左にずれても正の値になる。
  • 大きなずれほど強く罰する。ずれが 2 なら 4、3 なら 9。
  • なめらかで微分しやすい。モデルが漸化式なら \(J\) は入力の 2 次関数になり、平方完成で最小値が求まる。

例として、\(\Delta t = 1,\ \rho = 1\)、今の位置 \(x_0 = 0\)、目標 \(g = 4\)、2 手先まで予測する（\(N = 2\)）場合に、3 つの計画を採点してみる。

計画\(u_0,\ u_1\)\(x_1,\ x_2\)ずれの項入力の項\(J\)
A：ほどほど2, 22, 44 + 04 + 412
B：一気に4, 04, 40 + 016 + 016
C：ゆっくり1, 11, 29 + 41 + 115

B は 1 手で目標に着くが入力が大きすぎ、C は穏やかだが遅すぎる。3 つの中では A がいちばん良い。では、A よりさらに良い計画はあるのか。それを数式で求めるのが MPC だ（答えは \(J = 9.6\) の計画で、MPC の節で求める）。

1 手だけ実行して、計画し直す

コストが最小になる入力の列 \(u_0^*, u_1^*, \dots, u_{N-1}^*\) が求まっても、ロボットに送るのは最初の \(u_0^*\) だけだ（右肩の \({}^*\) は「最適な値」の印）。\(\Delta t\) 秒たったら状態を測り直し、それを新しい \(x_0\) として、また \(N\) ステップ先まで計画する。予測する範囲が時間とともに先へずれていくので、これをReceding horizon（後退ホライズン）と呼ぶ。

せっかく計画した残りを捨てるのはもったいなく見えるが、理由がある。モデルは現実と少しずれる（車輪がすべる、床が傾いている）し、人も動く。毎回測り直して計画し直せば、予測のずれを次の計画で取り戻せる。車の運転で、100 m 先まで見て走り方を考えつつ、ハンドルは今の分だけ切り、また前を見直すのと同じだ。

MPC（Model Predictive Control、モデル予測制御）も MPPI も、ここまでの「モデル → 予測 → コスト → 最初の 1 手だけ実行 → くり返し」という枠組みはまったく同じだ。違うのは「コストが最小になる入力の列をどう探すか」だけ。ここからは、その探し方を見ていく。

MPC：平方完成で谷底を求める

MPC は、コストが最小になる入力の列を数式で求める。モデルが漸化式でコストが 2 乗の和なら、コストは入力の 2 次関数になるので、高校数学の平方完成で解ける。

1 手先だけ予測する（\(N = 1\)）

いちばん簡単な \(N = 1\) から始める。入力は \(u_0\) の 1 つだけなので、単に \(u\) と書く。今のずれを \(d = x_0 - g\) とおくと \(x_1 - g = d + u\,\Delta t\) なので、コストは

\[ J(u) = (d + u\,\Delta t)^2 + \rho\, u^2 \]

展開して \(u\) について整理すると、\(u\) の 2 次関数になる。

\[ J(u) = (\Delta t^2 + \rho)\,u^2 + 2d\,\Delta t\,u + d^2 \]

\(u^2\) の係数 \(\Delta t^2 + \rho\) は正なので、グラフは下に凸の放物線で、頂点で最小になる。平方完成すると

\[ J(u) = (\Delta t^2 + \rho)\left(u + \frac{d\,\Delta t}{\Delta t^2 + \rho}\right)^{\!2} + \frac{\rho\, d^2}{\Delta t^2 + \rho} \]

よって、最適な入力は

\[ u^* = -\frac{\Delta t}{\Delta t^2 + \rho}\; d \]

微分で求めてもよい。\(J'(u) = 2(\Delta t^2 + \rho)\,u + 2d\,\Delta t = 0\) から同じ答えが出る。

例：\(\Delta t = 1,\ \rho = 1,\ x_0 = 0,\ g = 4\) なら \(d = -4\) で、\(J(u) = 2u^2 - 8u + 16 = 2(u - 2)^2 + 8\)。最適な入力は \(u^* = 2\)、そのときのコストは 8 になる。

答えは「ずれに比例した入力」

比例の係数を \(G = \dfrac{\Delta t}{\Delta t^2 + \rho}\) とおくと、答えは \(u^* = -G d\) と書ける。「目標からのずれに比例した大きさで、ずれを打ち消す向きに動かす」という形で、昔からあるP 制御（比例制御）と同じだ。1 手先だけ見る MPC は、P 制御と一致する。

  • \(\rho\) を大きくすると \(G\) が小さくなり、穏やかに近づく。
  • \(\rho = 0\) なら \(G = 1/\Delta t\) で、1 ステップで目標に飛び込む。ただし、ずれが大きいと入力がとても大きくなる。

くり返すと、等比数列で目標に近づく

Receding horizon で毎ステップ \(u^*\) を計算して動かすと、1 ステップ後のずれは

\[ d + u^*\,\Delta t = \left(1 - \frac{\Delta t^2}{\Delta t^2 + \rho}\right) d = \frac{\rho}{\Delta t^2 + \rho}\; d \]

になる。つまり、ずれは毎ステップ \(r = \dfrac{\rho}{\Delta t^2 + \rho}\) 倍になる。\(0 \le r < 1\) なので、ずれは公比 \(r\) の等比数列として 0 に近づき、\(m\) ステップ後のずれは \(r^m d\) だ。\(\Delta t = 1,\ \rho = 1\) なら \(r = \tfrac12\) で、位置は \(0 \to 2 \to 3 \to 3.5 \to 3.75 \to \cdots\) と、残りの半分ずつ近づく。

2 手先まで予測する（\(N = 2\)）

\(N = 2\) にすると、入力は \(u_0,\ u_1\) の 2 つになる。手計算しやすいよう \(\Delta t = 1,\ \rho = 1\) とすると、\(x_1 - g = d + u_0\)、\(x_2 - g = d + u_0 + u_1\) なので

\[ J(u_0, u_1) = (d + u_0)^2 + (d + u_0 + u_1)^2 + u_0^2 + u_1^2 \]

2 変数の 2 次関数の最小値は、高校数学の「1 文字を固定する」方法（いわゆる予選決勝法）で求まる。

予選：\(u_0\) を固定して、\(u_1\) だけを動かす。\(a = d + u_0\) とおくと、\(u_1\) を含む部分は

\[ (a + u_1)^2 + u_1^2 = 2u_1^2 + 2a\,u_1 + a^2 = 2\left(u_1 + \frac{a}{2}\right)^{\!2} + \frac{a^2}{2} \]

なので、\(u_1 = -\dfrac{a}{2}\) のとき最小値 \(\dfrac{a^2}{2}\) をとる。

決勝：その最小値を、\(u_0\) の関数として最小にする。

\[ \begin{aligned} J &= (d + u_0)^2 + \frac{(d + u_0)^2}{2} + u_0^2 = \frac{5}{2}u_0^2 + 3d\,u_0 + \frac{3}{2}d^2 \\ &= \frac{5}{2}\left(u_0 + \frac{3}{5}d\right)^{\!2} + \frac{3}{5}d^2 \end{aligned} \]

よって \(u_0^* = -\dfrac{3}{5}d\)、\(u_1^* = -\dfrac{d + u_0^*}{2} = -\dfrac{1}{5}d\)。コストの節の例（\(d = -4\)）なら \(u_0^* = 2.4,\ u_1^* = 0.8\) で、予測位置は \(x_1 = 2.4,\ x_2 = 3.2\)、コストは \(\tfrac35 \times 16 = 9.6\)。計画 A（12）より良い。

1 手先だけ見たとき（\(u^* = 2\)）より、最初の一手が大きい（2.4）。2 ステップ目のずれもコストに入るので、早めに近づいたほうが得になるからだ。このように、ホライズン \(N\) を変えると動き方も変わる。Receding horizon でくり返すと、ずれは毎ステップ \(1 - \tfrac35 = 0.4\) 倍になり、\(N = 1\) の 0.5 倍より速く縮む。

変数が多いとき

\(N\) が大きいと、入力が \(N\) 個ある 2 次関数の最小化になる。「ほかの入力を定数とみて、1 つの入力で微分したものが 0」という式を \(N\) 本並べると、\(N\) 元の連立 1 次方程式になる（さっきの予選・決勝は、これを 2 本で解いたことにあたる）。コンピュータはこの連立方程式をすぐに解ける。大学では行列を使って書き、LQR や 2 次計画法（QP）という名前で学ぶ。

入力には上限がある：定義域つきの最小値

実際のモーターには限界があり、速度は \(-u_{\max} \le u \le u_{\max}\) の範囲でしか出せない。このような条件を制約と呼ぶ。\(N = 1\) なら、これは「定義域が制限された 2 次関数の最小値」の問題そのものだ。答えは軸（頂点）と定義域の位置関係で場合分けする。

  • 頂点 \(u = -Gd\) が範囲の中にあれば、頂点が答え。
  • 頂点が範囲より右にあれば、右端 \(u_{\max}\) が答え（範囲の中では、右へ行くほど \(J\) が小さいから）。
  • 頂点が範囲より左にあれば、左端 \(-u_{\max}\) が答え。

まとめると「制約がないときの答えを求め、範囲からはみ出したら端で止める」だけでよい。\(\Delta t = 1,\ \rho = 1,\ u_{\max} = 1.5\) で \(x_0 = 0\) から \(g = 4\) を目指すと、最初は頂点が 2 で範囲の外なので \(u = 1.5\)。次は \(x = 1.5\) で頂点が 1.25 になり範囲の中、…と進み、位置は \(0 \to 1.5 \to 2.75 \to 3.375 \to 3.6875 \to \cdots\) と近づく。

\(N \ge 2\) で制約があると

入力どうしが互いに影響しあうので、制約がないときの答えを端で止めるだけでは最適にならないことがある。この場合は、制約つきの 2 次関数の最小化（2 次計画問題）を解く専用のプログラム（ソルバー）を使う。MPC が制約を正確に守れるのは、この計算をしているからだ。

2 輪ロボットでは平方完成できない

配膳ロボットや掃除ロボットの多くは、左右の車輪の速さを変えて進む差動 2 輪だ。状態は位置 \((x, y)\) と向き \(\theta\)、入力は前に進む速さ \(v\) と回る速さ（角速度）\(\omega\) で、モデルは三角関数を使って次のように書ける。

\[ \begin{aligned} x_{n+1} &= x_n + v_n \cos\theta_n\,\Delta t \\ y_{n+1} &= y_n + v_n \sin\theta_n\,\Delta t \\ \theta_{n+1} &= \theta_n + \omega_n\,\Delta t \end{aligned} \]

\(\Delta t\) 秒で進む距離 \(v_n\Delta t\) を、向き \(\theta_n\) に合わせて \(x\) 方向（\(\cos\)）と \(y\) 方向（\(\sin\)）に分けただけだ。

コストは、たとえば目標 \((g_x, g_y)\) までの距離の 2 乗に、人とぶつかりそうなときの罰 \(C_{\text{obs}}\) を足したものにする。

\[ J = \sum_{n=1}^{N} \Big[ (x_n - g_x)^2 + (y_n - g_y)^2 + C_{\text{obs}}(x_n, y_n) \Big] + \rho \sum_{n=0}^{N-1} \left( v_n^2 + \omega_n^2 \right) \]

\(C_{\text{obs}}\) は、たとえば「人との距離が 0.55 m 未満なら 1000、そうでなければ 0」のような罰だ。ところが、こうなると平方完成は使えない。

  • \(\theta_n\) が \(\cos\) と \(\sin\) の中に入るので、\(J\) は入力の 2 次関数ではなくなる。
  • 人との距離による罰は、0.55 m を境に 0 から 1000 へ急に跳ぶ。グラフが崖のような形になる。

そこで、数式で一発で解くのはあきらめ、良い入力に少しずつ近づけていく。

勾配降下法：坂を下る

入力を少し動かしたとき \(J\) が減る向きは、微分 \(J'(u)\)、つまりグラフの接線の傾きでわかる。傾きが負なら右へ、正なら左へ動かせば \(J\) は減る。そこで

\[ u \leftarrow u - \alpha\, J'(u) \]

をくり返す（\(\leftarrow\) は「右辺の値で置きかえる」の意味）。\(\alpha\) は 1 回に動かす量を決める正の数で、歩幅と呼ぶ。この方法を勾配降下法という。

例：\(J(u) = 2(u - 2)^2 + 8\) なら \(J'(u) = 4(u - 2)\) なので、1 回の更新で

\[ u_{\text{new}} - 2 = (1 - 4\alpha)(u - 2) \]

となり、頂点からのずれは公比 \(1 - 4\alpha\) の等比数列になる。\(\alpha = 0.125\) なら公比 \(\tfrac12\) で、\(u = 0 \to 1 \to 1.5 \to 1.75 \to \cdots\) と頂点の 2 に近づく。\(0 < \alpha < 0.5\) なら収束するが、\(\alpha = 0.5\) だと 0 と 4 を往復し、\(\alpha > 0.5\) だと発散する。歩幅は大きすぎても小さすぎてもいけない。

入力が何個あっても考え方は同じで、ほかの入力を固定したときの傾きを使って、各入力を少しずつ動かす。実際の MPC では、勾配降下法を改良したニュートン法や逐次 2 次計画法（SQP）などで、この計算を毎周期行っている。

傾きに頼る方法の弱点

  • 局所解：谷が 2 つあると、出発点に近い谷に落ちて止まる。人を左から回るか右から回るかのように、答えの候補が離れて複数あるときに起こりやすい。
  • 崖のようなコスト：ぶつかる・ぶつからないで値が跳ぶコストは、平らな所では傾きが 0 で、どちらへ動けばよいかわからない。
  • 微分の手間：モデルとコストの微分を用意する必要がある。

これらを、微分を使わずに乗り越えようとするのが MPPI だ。

MPPI：ばらまいて、重みつきで平均する

MPPI（Model Predictive Path Integral control）は、傾きを計算するかわりに、入力をランダムにたくさん試す。1 回の更新は次の 4 段階でできている。

  1. ばらまく：今の入力の案 \(u\) に、ランダムなゆらぎ \(\varepsilon^{(k)}\)（イプシロン）を足した候補を \(K\) 個つくる（\(k = 1, 2, \dots, K\)）。右肩の \((k)\) は「\(k\) 番目の候補」という意味で、累乗ではない。
  2. 走らせる：各候補の入力でモデル（漸化式）を計算して、軌跡を予測する。これをロールアウトと呼ぶ。
  3. 採点する：各軌跡のコスト \(S^{(k)}\) を計算する。\(S\) は \(J\) と同じもので、MPPI の論文の記号に合わせた。
  4. 重みつきで平均する：コストが低い候補ほど大きな重み \(w^{(k)}\) をつけて、ゆらぎを平均し、案に足す。
\[ \begin{aligned} u_{\text{new}} &= u + \sum_{k=1}^{K} w^{(k)}\, \varepsilon^{(k)} \\[4pt] w^{(k)} &= \frac{\exp\!\left(-\dfrac{S^{(k)} - S_{\min}}{\lambda}\right)}{\displaystyle\sum_{j=1}^{K} \exp\!\left(-\dfrac{S^{(j)} - S_{\min}}{\lambda}\right)} \end{aligned} \]

\(S_{\min}\) は \(K\) 個のコストの最小値、\(\lambda\)（ラムダ）は温度と呼ばれる正の数、\(\exp(x)\) は \(e^x\) のこと。式は長いが、中身は「正規分布でばらまく」「指数関数で重みにする」「重みつき平均をとる」という 3 つの高校数学でできている。順に見ていく。

正規分布でばらまく

ゆらぎ \(\varepsilon\) は、平均 0、標準偏差 \(\sigma\)（シグマ）の正規分布 \(N(0, \sigma^2)\) に従う乱数でつくる（この \(N\) は正規分布の記号で、ホライズンの \(N\) とは別）。0 の近くがよく出て、大きな値はめったに出ない、つりがね型の分布だ。

  • およそ 68% が \(-\sigma\) から \(\sigma\) の間に入る。
  • およそ 95% が \(-2\sigma\) から \(2\sigma\) の間に入る。

\(\sigma\) は「今の案から、どのくらい離れた所まで探すか」を決める。小さいと近くしか探さず、大きいと遠くまで探せるが、的外れな候補も増える。

指数関数で重みをつくる

重みの分子 \(e^{-(S^{(k)} - S_{\min})/\lambda}\) を見る。\(S^{(k)} - S_{\min}\) は「いちばん良い候補より何点悪いか」を表す 0 以上の数だ。関数 \(y = e^{-x}\) には次の性質がある。

  • いつも正。重みが負になることはない。
  • \(x = 0\) で 1、\(x\) が大きいほど小さい。悪い候補ほど軽くなる。
  • \(x\) が 1 増えるごとに \(1/e \approx 0.37\) 倍になる。差が開くほど、急に軽くなる。

最良の候補の分子はちょうど 1 で、ほかは 1 より小さい。分子の合計で割るのは、重みの合計を 1 にするためだ。こうすると \(\sum_k w^{(k)} \varepsilon^{(k)}\) は、確率と値をかけて足す期待値と同じ形の、重みつき平均になる。

1 手先の例を手で計算する

MPC と同じ例（\(\Delta t = 1,\ \rho = 1,\ x_0 = 0,\ g = 4,\ N = 1\)）で計算してみる。コストは \(S(u) = 2(u - 2)^2 + 8\) で、本当の答えは \(u = 2\) だ。今の案を \(u = 0\)、\(\sigma = 2\) として、ゆらぎを 5 個引いたら \(\varepsilon = -1,\ 0.5,\ 1,\ 2.5,\ 4\) だったとする（案が 0 なので、候補の入力もこの値になる）。\(\lambda = 1\) のとき：

同じ 5 個の候補で \(\lambda\) だけを変えると、重みと更新後の値は次のようになる。

  • \(\lambda\) が小さいと、最良の候補（2.5）だけを選ぶ。どの候補が引けたかという運に左右され、毎回の答えが跳ねやすい。
  • \(\lambda\) が大きいと、コストを無視したただの平均（5 個の平均は 1.4）に近づく。良い候補も悪い候補も同じ扱いになる。
  • ほどよい \(\lambda\) では、良い候補を中心に何本かを混ぜた平均になる。

「実質の本数」は \(1 \big/ \sum_k \big(w^{(k)}\big)^2\) で計算した値で、何本の候補を均等に平均したのと同じくらいかを表す。重みが 1 本に集中すると 1、全部が同じ重みなら \(K\) になる。Nav2 の説明でも、temperature は 0 に近いほどコストの低い候補を重視し、0 なら最良の候補だけを使い、非常に大きいとコストを無視した平均になる、とされている。

何手も先まで予測する MPPI

実際には、1 手ではなく \(N\) 手先までの入力の列 \(u_0, \dots, u_{N-1}\) をまとめて扱う。ゆらぎも列 \(\varepsilon^{(k)}_0, \dots, \varepsilon^{(k)}_{N-1}\) になり、コスト \(S^{(k)}\) は軌跡全体で 1 つの数にする。重みは候補ごとに 1 つで、どの時刻も同じ重みで平均する。

\[ u_n \leftarrow u_n + \sum_{k=1}^{K} w^{(k)}\, \varepsilon^{(k)}_n \qquad (n = 0, 1, \dots, N-1) \]

1 周期の流れを、Python 風の擬似コードで書くと次のとおり。

# u: 今の入力の案（長さ N のリスト）、x_now: 測った今の状態
for k in range(K):                       # 候補ごと（互いに独立なので並列に計算できる）
    eps[k] = [正規分布 N(0, σ²) の乱数 for n in range(N)]
    x = x_now
    S[k] = 0
    for n in range(N):                   # ロールアウト
        x = model(x, u[n] + eps[k][n])   # 漸化式で 1 ステップ進める
        S[k] += cost(x)
S_min = min(S)
w = [exp(-(S[k] - S_min) / λ) for k in range(K)]
w = [wk / sum(w) for wk in w]            # 合計を 1 にする
for n in range(N):
    u[n] += sum(w[k] * eps[k][n] for k in range(K))
send(u[0])                               # 最初の 1 手だけ実行する
u = u[1:] + [u[-1]]                      # 1 つずらして、次の周期の案にする

model と cost は、モデル（漸化式）とコスト関数。send はロボットへの指令の送信。

最後の行のように、今回の答えを 1 ステップずらして次の周期の出発点にする（ウォームスタート）。前回の答えのまわりから探し始めるので、1 周期に 1 回の更新でも、くり返すうちに良い答えに近づいていく。

候補どうしは互いに関係なく計算できるので、並列計算に向いている。大量の候補を GPU で同時に計算する実装も多い。Nav2 の MPPI は CPU のベクトル演算を使い、ふつうの CPU（第 4 世代の Core i5）でも 50 Hz 以上で動くと説明されている。

実装でよく加わる工夫

  • 入力の上限で候補を切り詰める（クリップ）。上限の内側の値どうしを重みつき平均すれば、結果も上限の内側に収まる。
  • 論文の式では、状態のコストに加えて「案 \(u\) とゆらぎ \(\varepsilon\) の積」に比例する項もコストに足す。ゆらぎの付け方に由来する補正で、Nav2 の gamma はこの項にかかる係数にあたる。
  • 乱数による細かいガタつきを抑えるため、入力の列をなめらかにしたり、入力の変化の大きさをコストに入れたりする。
  • 1 周期の中で更新を何回かくり返すこともある（Nav2 の iteration_count。既定値は 1 で、回数を増やすより候補を増やすことが勧められている）。

2 輪ロボットで MPPI を動かす

差動 2 輪のロボット（左の円）が、人（灰色の円）をよけてゴール（×）へ向かう。毎ステップ、\(K\) 本の候補を正規分布でばらまいてロールアウトし、重みつき平均で入力の列を更新して、最初の 1 手だけを実行している。オレンジの線が候補で、濃いほど重みが大きい。太い線は、更新した入力の列で予測した軌跡だ。

  • \(\lambda\) を 0.01 くらいまで下げると、毎回その場で最良の 1 本だけを選ぶので、軌跡がガタつく。100 以上に上げると、ただの平均に近づいて案がほとんど良くならず、なかなか前に進まなくなる。
  • \(\sigma\) を小さくすると、案の近くしか探さないので回り道を見つけるのが遅れ、到着に時間がかかる。
  • \(K\) を 20 にすると、良い候補を引けるかが運次第になり、動きが不安定になりやすい。

なぜ指数関数なのか発展

重みは「コストが低いほど大きい正の数」なら何でもよさそうに見える。たとえば \(1/S\) でもよいはずだ。それでも MPPI が \(e^{-S/\lambda}\) を使うのには理由がある。

コストの差だけで決まる

2 つの候補の重みの比は、指数法則 \(e^{a}/e^{b} = e^{a-b}\) から

\[ \frac{w^{(i)}}{w^{(j)}} = \frac{e^{-S^{(i)}/\lambda}}{e^{-S^{(j)}/\lambda}} = e^{-(S^{(i)} - S^{(j)})/\lambda} \]

となり、コストの差だけで決まる。全員のコストに同じ数を足しても、重みは変わらない。コストには「ゴールまでの距離」のように、どの候補にも共通する大きな部分がよく含まれるので、これは大事な性質だ。\(1/S\) だと、コストが 1 と 2 の候補の重みの比は 2 倍なのに、全員に 100 を足しただけで \(102/101 \approx 1.01\) 倍に縮んでしまう。

重みの式で \(S_{\min}\) を引いてよいのも、このためだ。分子も分母も \(e^{S_{\min}/\lambda}\) 倍されるだけで、約分で消える。引くのには実用上の理由もある。コストが 1000 くらいになると、\(e^{-1000}\) はコンピュータで表せる最小の数より小さくなって 0 として扱われ、すべての重みが 0 になって割り算ができなくなる。\(S_{\min}\) を引けば、最良の候補の分子はかならず 1 なので、この問題は起きない。

この形は、機械学習ではソフトマックス（softmax）、物理では温度 \(\lambda\) のボルツマン分布と同じ形をしている。\(\lambda\) を温度と呼ぶのはこのためだ。

「コストを下げる」と「1 つに賭けない」のつり合い

\(K\) 個の候補に、合計が 1 になる割合 \(q_1, \dots, q_K\)（どれも 0 以上）を配ることを考える。次の \(F\) を最小にする配り方を求めたい（\(\log\) は自然対数）。

\[ F(q) = \sum_{k=1}^{K} q_k\, S^{(k)} \;+\; \lambda \sum_{k=1}^{K} q_k \log q_k \]
  • 第 1 項は、割合で平均したコスト。最良の候補に全部を配ると最小になる。
  • 第 2 項は、配り方の偏り。1 つに全部を配ると最大の 0、均等に配ると最小の \(-\log K\) になる（\(q_k = 0\) の項は 0 と約束する）。

つまり \(F\) の最小化は、「平均コストを下げたい」と「1 つに賭けすぎず、何本かに分散させたい」のつり合いを \(\lambda\) で決める問題だ。分散させておけば、たまたま低いコストが出た 1 本に振り回されにくい。答えは

\[ q_k^* = \frac{e^{-S^{(k)}/\lambda}}{Z}, \qquad Z = \sum_{j=1}^{K} e^{-S^{(j)}/\lambda} \]

で、MPPI の重みそのものになる。証明は数学 III の範囲でできる。

証明を見る（数学 III）

1. \(x > 0\) で \(\log x \le x - 1\)（等号は \(x = 1\) のときだけ）を示す。\(f(x) = x - 1 - \log x\) とおくと \(f'(x) = 1 - \dfrac{1}{x}\) なので、\(f\) は \(0 < x < 1\) で減少し、\(x > 1\) で増加する。よって最小値は \(f(1) = 0\) で、\(f(x) \ge 0\)。

2. \(\log q_k^* = -\dfrac{S^{(k)}}{\lambda} - \log Z\) より \(S^{(k)} = -\lambda \log q_k^* - \lambda \log Z\)。これを \(F\) に代入し、\(\sum_k q_k = 1\) を使うと

\[ F(q) = \lambda \sum_{k} q_k \log \frac{q_k}{q_k^*} \;-\; \lambda \log Z \]

3. 右辺の和が 0 以上であることを示す。\(q_k > 0\) の項だけを足す（\(q_k = 0\) の項は 0）。1. より \(\log \dfrac{q_k^*}{q_k} \le \dfrac{q_k^*}{q_k} - 1\) なので

\[ \sum_{k} q_k \log \frac{q_k}{q_k^*} = -\sum_{k} q_k \log \frac{q_k^*}{q_k} \;\ge\; -\sum_{k} q_k \left( \frac{q_k^*}{q_k} - 1 \right) = 1 - \sum_{k} q_k^* \;\ge\; 0 \]

（最後の和は \(q_k > 0\) の \(k\) についてだけとるので、1 以下になる。）よって \(F(q) \ge -\lambda \log Z\) で、等号はすべての \(k\) で \(q_k = q_k^*\) のときだけ成り立つ。したがって、\(F\) を最小にする配り方は \(q^*\) だ。■

大学での名前

第 2 項に \(\log K\) を足したものは、均等な配り方からのKL ダイバージェンス（分布の離れ具合）と呼ばれる。また、\(F\) の最小値 \(-\lambda \log Z\) は自由エネルギーと呼ばれる。MPPI の論文は、この 2 つの考え方を使って重みの式を導いている。

MPC と MPPI のつながり発展

MPPI は微分を使わないが、実は「坂を下る」ことと深い関係がある。1 手先の例 \(S(u) = a(u - c)^2 + b\)（\(a > 0\)、谷底は \(u = c\)）で、候補の数 \(K\) を限りなく増やしたときの更新を計算してみる。

今の案を \(\bar u\)（ユーバー）とすると、候補 \(u\) の出やすさは、中心 \(\bar u\) の正規分布の山 \(e^{-(u - \bar u)^2/(2\sigma^2)}\) に比例する。\(K\) が十分大きいとき、重みつき平均は、\(u\) の値を「出やすさ × 重み」に比例する割合で平均したものになる。その割合の山は、指数法則により、指数部分の足し算で書ける。

\[ e^{-\frac{(u - \bar u)^2}{2\sigma^2}} \times e^{-\frac{a(u - c)^2}{\lambda}} = \exp\!\left[ -\left( \frac{(u - \bar u)^2}{2\sigma^2} + \frac{a(u - c)^2}{\lambda} \right) \right] \]

（重みのうち \(e^{-b/\lambda}\) の部分は、すべての候補に共通なので約分で消える。そのため省いた。）かっこの中は \(u\) の 2 次式なので、平方完成すると \(A(u - m)^2 + B\)（\(A > 0\)、\(B\) は定数）の形になる。つまり割合の山は、ふたたび中心 \(m\) のつりがね型（正規分布の形）だ。正規分布の平均は山の中心なので、更新後の値は \(m\) になる。計算すると

\[ m = \frac{\lambda\,\bar u + 2a\sigma^2 c}{\lambda + 2a\sigma^2} = \bar u + \beta\,(c - \bar u), \qquad \beta = \frac{2a\sigma^2}{\lambda + 2a\sigma^2} \]
平方完成の途中を見る

\(P = \dfrac{1}{2\sigma^2},\ Q = \dfrac{a}{\lambda}\) とおくと、かっこの中は

\[ \begin{aligned} P(u - \bar u)^2 + Q(u - c)^2 &= (P + Q)\,u^2 - 2(P\bar u + Qc)\,u + (P\bar u^2 + Qc^2) \\ &= (P + Q)\left(u - \frac{P\bar u + Qc}{P + Q}\right)^{\!2} + B \end{aligned} \]

よって \(m = \dfrac{P\bar u + Qc}{P + Q}\)。分母と分子に \(2\sigma^2\lambda\) をかけると、\(P \times 2\sigma^2\lambda = \lambda\)、\(Q \times 2\sigma^2\lambda = 2a\sigma^2\) なので、上の式になる。

\(0 < \beta < 1\) なので、MPPI の 1 回の更新は「案を谷底 \(c\) に向かって、割合 \(\beta\) だけ近づける」ことになる。くり返せば、案と谷底の差は公比 \(1 - \beta\) の等比数列で縮んでいく。

  • \(\lambda \to 0\) なら \(\beta \to 1\)：一気に谷底へ行く。
  • \(\lambda \to \infty\) なら \(\beta \to 0\)：ほとんど動かない。ゆらぎの平均は 0 だからだ。
  • 例の \(a = 2,\ c = 2,\ \sigma = 2,\ \bar u = 0\) では、\(\lambda = 1\) で \(m \approx 1.88\)、\(\lambda = 4\) で \(m = 1.6\)、\(\lambda = 100\) で \(m \approx 0.28\)。5 個の候補で計算した表の値とずれるのは、候補が少ないからだ。図 9 で \(K\) を増やすと、この値に近づいていく。

さらに、\(S'(\bar u) = 2a(\bar u - c)\) から \(c - \bar u = -\dfrac{S'(\bar u)}{2a}\) と書きかえると

\[ m = \bar u - \frac{\sigma^2}{\lambda + 2a\sigma^2}\; S'(\bar u) \]

となる。これは歩幅 \(\alpha = \dfrac{\sigma^2}{\lambda + 2a\sigma^2}\) の勾配降下法そのものだ。\(\sigma\) が小さいときは \(\alpha \approx \sigma^2/\lambda\) になる。MPPI は、微分を計算しないかわりに、ばらまいた候補のコストの違いから坂の向きを感じ取って下っている、と言える。

違いは、傾きを 1 点で測るか、幅 \(\sigma\) の範囲でならして測るかだ。幅をもって測るので、小さなでこぼこや崖のようなコストに惑わされにくく、\(\sigma\) が大きければ離れた谷にも候補が届く。そのかわり、候補が少ないと平均がぶれる。

図 7 の例でも、左の谷に届いた候補はコストが低いので重みが大きくなり、案は左へ引っぱられる。ただし、左右の谷に同じくらいの重みが分かれると、平均が真ん中の山（ぶつかる側）に来てしまうことがある。\(\lambda\) を小さめにして良い側に重みを寄せるのはその対策になるが、小さくしすぎると実質の本数が減り、答えがぶれやすくなる。

補正項の係数gamma0.015論文の「案 × ゆらぎ」の項の係数。なめらかさ（大）と省エネ（小）のつり合いを決める
コスト \(S\)critics—障害物、経路への追従、ゴールへの接近などのコスト（critic）を選び、足し合わせる

既定値は Nav2（Jazzy）の設定ガイドによる。版によって変わることがあるので、使っている版のドキュメントで確かめること。

たとえば temperature を下げるとコストの低い候補だけを信じるようになり、反応は鋭くなるがガタつきやすくなる。batch_size を増やすと良い候補を引ける確率が上がるが、計算が重くなる。図 10 のデモで \(\lambda\) と \(K\) を動かしたときの変化は、これらのパラメータを大きく・小さくしたときの効き方の目安になる。ただし、コストの大きさが違うので、\(\lambda\) の値そのものは Nav2 の temperature とは比べられない。

用語集

モデル予測制御（MPC）
モデルで未来を予測し、コストが最小になる入力の列を求め、最初の 1 手だけ実行することをくり返す制御。
MPPI（Model Predictive Path Integral control）
MPC の一種。入力をランダムにばらまいた候補をモデルで走らせ、コストから計算した重みで平均して、入力の列を更新する。名前の Path Integral（経路積分）は、導出のもとになった経路積分制御の理論に由来する。
状態と入力
状態は今の様子（位置、向き、速度など）。入力はこちらが決められる量（速度の指令、モーターの出力など）。
モデル
今の状態と入力から、次の状態を計算する式。この資料では漸化式。
予測ホライズン
何ステップ先まで予測するか。ステップ数 \(N\) と 1 ステップの時間 \(\Delta t\) の積が、予測する時間になる。
コスト関数
計画の悪さを表す数。小さいほど良い。
Receding horizon（後退ホライズン）
先まで計画し、最初の一部だけ実行して計画し直すことをくり返す方式。
P 制御（比例制御）
目標とのずれに比例した入力を出す制御。
制約
入力の上限など、守らなければならない条件。
2 次計画問題（QP）
2 次関数を、1 次式で書いた制約のもとで最小にする問題。制約のある MPC は、毎周期これを解くことが多い。
勾配降下法
傾き（微分）と逆の向きに少しずつ動かして、関数の最小値を探す方法。
局所解
まわりの中では最小だが、全体では最小でない点。
ロールアウト
ある入力の列でモデルを先まで計算し、軌跡を予測すること。
温度
MPPI で、コストの差をどれだけ重く見るかを決める数 \(\lambda\)。小さいほど、低コストの候補に重みが集中する。
ソフトマックス
数の組を、指数関数で正の数にしてから、合計が 1 になるように割る変換。MPPI の重みは \(-S/\lambda\) のソフトマックス。
ウォームスタート
前回の答えを出発点にして、次の最適化を始めること。
差動 2 輪
左右の車輪の速さの差で曲がる、移動ロボットの方式。
